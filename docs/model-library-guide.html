模型添加一次，各场景直接选择

在「模型库」添加模型，选择厂家，填写 Key 后「连接并保存」。地址、型号和 Key 统一保存在本浏览器，翻译、网页总结与日周月年回顾不再各配一份。

  • 翻译：在模型库下方选择翻译的默认模型和备用。
  • 总结与回顾：到「总结设置」选择已保存模型，无需重填 Key。网页、每日、每周、每月、每年和专题共用这个选择。
  • 各自选择：两个场景可以选同一个连接，也可以选不同连接；默认与备用顺序分别保存。
  • 多 Key：同厂家不同 Key 仍是不同连接，不按地址自动合并，避免错用账户。
  • 翻译专用模型：例如 qwen-mt-flash 可以用于翻译，总结下拉框会标为「仅翻译」，禁止选用。

模型库最多保存 32 个连接，每场景最多使用 8 个。选择、修改备用顺序和从场景移除连接不发起连接测试；新保存连接会发送固定测试词，使用少量额度。自动总结默认关闭，配置模型不会自动开启。开启弹窗顶部开关后，后台网页和周期任务才按权限规则使用总结模型；关闭不影响手动总结与生成回顾。

新增模型默认勾选「在此浏览器长期记住密钥」，也可以取消，只保留当前浏览器会话。升级保留旧模型原来的保存方式，不把旧会话 Key 自动改为长期保存。明文 Key 不显示在列表，不发送给网页，不进入词库或知识导出。

编辑和删除会影响哪些场景

编辑模型库中的连接时，所有引用它的场景同步使用新配置和 Key。从一个场景「移出本场景」只移除引用，模型与 Key 留在模型库，其他场景继续使用。

在模型库删除连接会同时删除其 Key 和场景引用，界面会列出受影响的场景；原默认连接删除后优先使用该场景已启用的备用，没有备用时需要重选。数据与隐私中的「清除模型库全部 Key」会影响所有引用场景，但保留模型配置和本地阅读资料。

正在用于总结的模型不能直接改成翻译专用 MT 型号，需先明确从总结场景移除。新增未使用的模型不会取消正在处理的其他模型任务。

旧配置自动迁入

升级时将原翻译、总结连接登记到同一个模型库，保留原默认、备用顺序、Key 归属及保存期限。同一个地址的不同 Key 不自动合并；旧数据里即使碰巧使用相同连接 ID，也会保留为独立记录。

先写入新的凭据记录，再保存引用关系，最后清理旧存储。已经清除的 Key 不会在重新加载后被旧数据复活。原词库、阅读轨迹和翻译偏好不参与模型迁移。

轨迹和回顾自动检索

在「我的轨迹」「阅读回顾」输入关键词，停止输入约 350 毫秒 后自动检索；中文输入法正在组词时不检索，完成输入后再更新。清空关键词恢复结果，日期、来源、项目和标签选择后自动更新，不需要点击「筛选」。

检索只读取本地资料，不调用模型。旧请求迟到时不会覆盖新的检索条件。分页、生成回顾、导出和清理继续使用当前范围；未保存的备注草稿仍保留。

词库保存在本地，升级不重建

词句继续使用原 shiyi-vocabulary 本地数据库及原记录 ID。升级只补齐缺少的存储结构，不删除词句、不换数据库名称。已有释义不受模型库调整影响。

每次新增、编辑、删除、撤销或恢复词句后，自动在浏览器本地存储更新一份副本。数据与隐私页面显示副本数量与更新时间，可手动重试。正常数据结构升级和浏览器重启保留词库；数据库被重新创建时，可从该浏览器内仍存在的副本恢复。主动删除词句后不会被旧副本重新添加。

自动副本仍在同一个浏览器的扩展存储内，不能替代独立文件。浏览器卸载扩展时会清理扩展数据，这是浏览器的存储行为。Chrome 官方说明

为什么换目录后配置和数据会变空

v0.14.1 及更早的开发者安装包没有固定插件身份。解压到新文件夹并重新“加载已解压的扩展”，浏览器会登记另一份插件，模型、Key、词库、轨迹均按插件 ID 隔离。数据已经存到本地，但新 ID 不能读取旧 ID 的数据。原来只验证了原目录覆盖升级，未覆盖换目录安装，这个交付缺口在 v0.14.2 修复。

新安装包内置固定公开标识，同一浏览器资料中换目录加载仍保持同一个 ID。公开标识不是 API Key 或私钥，不包含账户信息。不能先卸载：浏览器卸载会清理扩展本地数据。Chrome 与 Edge、不同浏览器资料之间不会自动共享数据。Chrome 固定标识说明 · 存储生命周期

已有旧版不能直接套用新标识，否则反而会再次隔离原数据。升级工具保留旧安装的原目录和原标识，包括原先没有固定标识的情况。以后继续升级这份原插件，无需重新配置。应用更新和重新加载会清空仅会话保存的 Key；勾选长期保存的 Key 则随原身份保留。

保留旧数据的升级方法

  1. 解压新版安装包。macOS 运行 升级点译.command，Windows 运行 升级点译.cmd；需要本机 Python 3。也可运行 python3 upgrade/install.py。
  2. 工具只读取 Chrome / Edge 安装登记中的目录信息，列出旧点译，优先标出仍有本地数据文件的那份。选择你原来使用的安装目录，核对后继续。找不到时可手动输入原目录。
  3. 工具仅覆盖程序文件，保留原插件身份；旧程序文件备份到原目录旁的 .dianyi-code-backups。它不读取 API Key，不复制、移动或改写浏览器存储；代码备份不等于阅读数据备份。
  4. 到 chrome://extensions 或 edge://extensions，找到原来那条点译，点击“重新加载”。不要先删除，不要再加载另一份新目录。若为首次安装，选择工具准备的固定目录加载即可。
  5. 不使用工具时，也可将新版文件覆盖进原目录，但旧版原先没有 key 字段时必须继续保留这一点；建议用工具完成，避免手工改变身份。

macOS 已使用真实 Chrome 验证，Windows 包装入口和原生 Edge 尚未在对应系统单独验收。新固定身份的安装可直接换目录升级；旧安装继续由升级工具保留原身份。管理页“数据与隐私”会显示当前属于哪种情况。

已经变空时找回原数据

  • 先不要删除任何旧点译或旧文件夹。在扩展管理页查找之前加载的那条，进入其管理界面确认模型、词库和轨迹；数据可能仍在旧 ID 下。
  • 运行升级工具，选择标有本地数据文件的原目录，再重新加载原插件。不要把空的新实例当成旧数据已经被删除。
  • 只有 Key 需要重填、但模型和词库还在时，检查是否选了“仅本次会话”；这与换目录导致整份数据隔离不同。
  • 需要更换浏览器或卸载时，先导出词库 JSON 和阅读知识。在新安装中通过“恢复词库”合并 JSON；模型 Key 当前没有跨浏览器自动迁移。
  • 已卸载或清理浏览器数据且没有独立备份时，不能保证找回。不要把同一扩展内的自动副本当成卸载后的恢复保证。

恢复在本地完成，不请求模型。先校验整批文件，再一次性合并；相同原文和目标语言保留当前释义，只新增缺少的词句。ID 碰撞时为新词句生成新 ID，不覆盖其他词条。词句来源去除查询参数，密钥等额外字段不会导入。单文件上限 16 MB、每批最多 20,000 条，超限请分批恢复。

如自动副本损坏，保留原副本并提供恢复说明，不让整个插件无法使用。原文数据库写入成功而副本更新失败时，会清楚显示副本状态，可以重试或导出文件。

本轮验证使用真实 Chrome、旧版本安装 ZIP、同一安装目录和隔离临时资料。测试词句与 Key 均为合成数据，不读取用户浏览器或付费模型账户。原生 Edge 尚未单独验证。
