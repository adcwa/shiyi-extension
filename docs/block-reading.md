# 点译 v0.9.1 · 长文问题定位与批量阅读方案

2026-11-03

## 结论

短词释义与长文阅读使用独立路径。短词保留下划线、悬浮与括号；长选区和整页采用语义内容块。默认双语对照，可以切换仅译文或恢复原文，整页期间暂停划词标记。

推荐双语作为默认阅读方式：上下文与原文始终可见，遇到专业术语容易核对。仅译文用于连续阅读。两种方式共享一次请求结果，切换不重新调用模型。

## 问题定位

复现命令：`npm run test:long`，实际在隔离 Chromium 中加载扩展并预置一条翻译成功后的长句记录，经过正常启用、词库扫描和显示路径。不依赖第三方模型或账号。

| 对照 | 观察 | 判断 |
| --- | --- | --- |
| v0.1.1，355 字符段落，有强调元素 | 3 个下划线片段、1 个长括号、0 个译文块 | 长段落沿用单词装饰；内联元素让长标记碎片化 |
| 同样文本，移除强调元素 | 1 个下划线、1 个长括号、0 个译文块 | 纯文本同样影响阅读，主要原因是显示模型而非强调元素本身 |
| 原用例连续扫描 3 次 | 仍为 3 个下划线、1 个括号 | 当前用例排除重复扫描导致重复插入 |
| v0.2.0，同一用例 | 0 个下划线、0 个括号、1 个独立译文块 | 长文脱离短词装饰，原段落 HTML 不变 |

旧版本把所有收藏文本编入相同 Trie。命中长句后按文本节点拆出 span，横跨原有 em／a 等元素；最后一个碎片追加一段括号释义。即使偏移完全正确，长文仍会满段画线、缩小字号和挤占行内空间。仅调整偏移、线条颜色或括号字号无法解决阅读结构问题。

复现材料保存在 `verification/long-text-0.1.1*.json` 与 `verification/long-text-0.2.0*.json`，包含实际截图与节点数量，不包含凭据。

## 方案比较

| 方式 | 取舍 | 采用范围 |
| --- | --- | --- |
| 下划线＋悬浮／括号 | 适合识记短词；长译文干扰行内排版 | 同块内不超过 160 字符的短词句 |
| 段后追加译文 | 原文易核对，页面事件与元素保留；页面会变长 | 默认长选区和整页双语 |
| 修改原文本节点 | 连续阅读，原有链接／强调／控件保留；依赖模型返回可靠片段对应关系 | 仅译文 |
| 替换整个容器 HTML／克隆整段 | 容易破坏链接、事件、表单与框架状态，HTML 模型输出还引入执行风险 | 不采用 |
| 单次发送整页 HTML | 结构噪声大、容易超时或截断，难以恢复和局部重试 | 不采用 |

段落作为翻译单位、默认双语并提供仅译文，参考了[沉浸式翻译的官方使用方式](https://immersivetranslate.com/docs/usage/)。点译的具体 DOM 保留、取消与缓存方案由本项目实现。

## 内容块识别与排版

- 优先识别段落、标题、列表项、表格单元格、图注及控件；段落里的链接／强调作为片段保留，独立导航链接单独处理。
- 原文节点与位置有明确映射。同一容器内的局部文字不会误当成整个容器，避免把页眉小标签的译文追加到整篇文章末尾。
- 普通段落在段后追加译文；导航、短按钮和短表格标签按片段在文字区域紧凑显示，纯数字徽标保留原样，译文不会成为新的图标列或计数列。较长标签仅在内部换行，正文列表保留段落关系。
- 译文沿用来源字体，仅调整文字颜色，不加底色、边框与侧线；双语字号减小 2px、行高同比缩放，仅译文保持原字号，在正常文档流中换行；按所在区域背景与主题变化适应窄栏和暗色页面。长文不加下划线、不加括号。
- 整页仅处理主文档当前已加载的可读文字；不处理 iframe、Shadow DOM、PDF、图片或 Canvas。
- 不发送输入值、编辑器内容、代码块、隐藏内容和不翻译区域。段内代码由本地占位符保护，完整代码不发送到模型。

## 请求与片段对应

长段落每个分片最多 1800 个字符、60 个片段；优先在完整句子或换行处拆分，其次在空白处切分，不截断 Unicode 字符。一个段落的所有分片完成后再显示。短块默认最多 16 块合并，可配置 1–64；每批字符与片段预算随块数增长，默认 9600 字符／192 片段，全局上限 24000 字符／768 片段。每个批次一次请求，最多两个并发。首个可见块单发，后续按当前视口顺序批量处理；首次 400 块预算也优先包含当前位置。

请求携带稳定块 ID 和块内 `{id,text}` 片段，模型只需返回两级 ID 对应的译文，不重复生成整段全文；兼容服务仍可返回旧版完整译文字段。后台校验片段数量、标识、非空文本、保护占位符与响应长度，按 ID 查找而非按响应位置写回。缺失、重复或不完整的片段按块隔离，不影响同批有效结果；失败块保留原文，用户重试时逐段请求，不解析模型 HTML。响应过长或超时的批次也可通过逐段重试恢复。

双语显示完整译文；仅译文把各片段写入原有 Text 节点的 data，不替换链接、图片或容器。片段结构校验不能自动判定模型的语义质量，具体语序与链接文本仍取决于所选模型的翻译和对齐能力。

Chrome 的 MV3 后台存在空闲、长事件和 fetch 响应生命周期限制，因此整页任务由页面维护，后台只处理短而独立的请求，每次仍受现有 5–25 秒超时限制，避免把整页包装成一个持续很久的后台事件。[Chrome 官方生命周期说明](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle)

## 恢复、变化与计费控制

1. 双语／仅译文切换直接复用已获取结果，不重新发送。
2. 停止会保留已完成块；继续只处理未完成块；失败重试针对失败块。
3. 恢复会取消在途请求，移除追加块并还原插件修改过的文字。晚到结果由任务代次、文档身份与取消状态拦截。
4. 只在当前文字仍等于插件所写译文时恢复原快照；网站后来改写的文字优先，避免用过时原文覆盖新内容。Text.data 允许保留元素本身与绑定事件。[MDN CharacterData.data](https://developer.mozilla.org/en-US/docs/Web/API/CharacterData/data)
5. 路由、启用状态或影响翻译的设置变化会清理旧任务，避免新页面混入旧结果。
6. 新加载内容只提示更新，点击后处理。首次 400 块或约 12 万字符，较大页面明确显示剩余进度并允许继续；不自动翻译无限滚动内容。
7. 401／403、密钥／权限缺失、429 等会暂停队列，避免对每个段落重复发送无效请求。普通块失败可以稍后重试。

## 本地数据兼容

原词库、厂家选择、自定义连接和密钥保存方式不清空。数据库升级至版本 2 时仅新增页面暂存。超过 160 字符的旧词库记录不再进入下划线 Trie；完整内容块匹配时显示独立译文，仍可在词库编辑／删除。

按段、整页结果沿用独立的 block-v1 缓存身份，不写词库、不广播成新的词条。合并前过滤缓存命中与相同片段身份，旧版缓存可直接复用。缓存身份包含原片段、目标语言、风格、提示词、厂家、地域、模型和端点；本地缓存沿用最多 1000 条、约 7 天有效的规则。

页面映射另外按完整网址与翻译语义配置暂存，本机保留约 7 天、50 页／20 MiB，单页 3 MiB。刷新只恢复核对通过的原文结构与译文，不自动请求；重新翻译旋转修订并绕过旧缓存，替换本页结果。变化的原文或链接保留原文。详细数据流程见[实现说明](architecture.md)。

目标为中文时先跳过中文节点与内容块，渲染时再核对，旧缓存的中文重复结果也不追加。混合段落仅追加外语部分译文。千问 MT 使用独立纯文本协议、保护标记与严格片段核对，标记丢失时受控回退；其他模型保持原批量 JSON 协议。

## 验收

- 原始长段落复现从失败转为通过，强调元素和原始 HTML 保留；重复扫描无重复块。
- 实际浏览器验证双语／仅译文、跨段选区、万字分批、停止／继续、恢复、局部重试、动态新增、在途网页改写和路由变化。
- 检查链接与按钮节点身份及事件保留、表单值保留、源结构恢复、HTML 仅作为文本、请求中不含输入内容或凭据。
- 390px 窄页面和暗色页面无横向溢出，按原网页流式阅读。

自动化使用真实 MV3 扩展与本地确定性 HTTP 兼容服务，不评价真实服务商的翻译质量，也未使用用户的 Key 或额度。完整记录见 `verification/page-translation-e2e.json`。
