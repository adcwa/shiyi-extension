# 点译 v0.7.1 · 重复词标记闪烁修复

2026-11-03

## 根因

旧版针对无关计数器更新增加了「整组结果一致则跳过」检查，但两个重建入口仍然存在：

1. 实际划词收藏、编辑词库或修改偏好后，refresh 清除整页标记，再提交异步扫描。
2. 同段有一个真实命中新增、消失或改变时，annotationsCurrent 返回 false，startScan 清除整个扫描根节点，再等待另一次空闲回调重建。

因此，同一词多处出现时，只有一处变化，其他下划线和括号也会一起消失再出现。高频页面变化和词库同步会重复触发。清除和重建处于不同回调，浏览器有机会绘制没有标记的中间帧。最终数量正确和纯计数器测试都无法发现这个缺口。

## 最小复现与测量

真实加载未改写的 MV3 扩展，用本地固定响应 HTTP 服务完成实际鼠标划词、翻译、收藏。正文有三个 Curiosity 和一个 Serendipity，先收藏 Curiosity，再收藏 Serendipity。另在同段末尾交替增加、移除一个 Curiosity。通过 MutationObserver 计数，并逐帧检查已有标记是否整体缺失；同时检查最初节点身份。

| 场景 | v0.7.0 | v0.7.1 |
| --- | --- | --- |
| 同段再收藏另一词，已有 3 处标记保留 | 0 / 3；移除 3 处 | 3 / 3；移除 0 处 |
| 同段动态增删另一处重复词，已有 4 处标记保留 | 0 / 4 | 4 / 4 |
| 同一动态序列，下划线移除次数 | 14（包括被页面替换的动态项） | 2（仅被页面替换的动态项） |
| 同一动态序列，括号模式已有 4 个释义节点保留 | 0 / 4 | 4 / 4 |
| 动态序列中已存标记缺失的画面 | 3 帧 | 0 帧 |

基线：verification/selection-stability-baseline-0.7.0.json。当前：verification/selection-stability-0.7.1.json。具体帧数随调度变化；节点保留和移除次数是主要回归条件。

## 修复方案

- 词库同步与正文动态变化使用同一条增量对齐路径，取消两处预清空入口。恢复原文、停用、进入整页阅读等明确模式切换仍正常移除装饰。
- 以真实 Text 节点、命中范围、词条 ID 判断每个实际出现位置。一个词条可以对应多个独立标记，不能只按词条 ID 替换。
- 保留仍有效的 span。只解包失效片段、插入新片段；已有括号仅就地更新内容和颜色。匹配计划与变更在同一次回调内完成。
- 扫描统一跳过插件注入释义，保持源文本连续；跨强调元素的短语、词边界和最长命中仍正确。
- 扫描继续按 200 个节点／8ms 分片，等待期间保留现有标记。取消、任务代次和选区保护继续生效。
- 对插件拆分的源 Text 节点记录所属原始序列，只合并同一序列中相邻的自有分片。中间标记先删除、后撤销也能精确还原，保留原 Text 节点、链接与事件。

该修复直接随普通划词功能启用，使用原有设置和权限，不增加调试参数或功能开关。

## 回归范围

新增专项覆盖真实划词后再学习其他词、同段动态增删、连续五次词库广播、连续换色、删除撤销、精确恢复、悬浮及括号两种模式，以及普通段落、强调和链接、相邻导航、空白字符、换行和嵌套段落。除最终数量，还检查未变化节点保留、无嵌套标记和无缺失帧。

原有专项继续覆盖 180 处重复词、跨元素短语、词边界更改、真实新增删除、黑名单暂停恢复。整页阅读、缓存恢复、语言切换、模型连接和键盘操作按现有浏览器流程回归。长期缓存、用户模型、密钥和词库格式均未变更。

```sh
node scripts/e2e.mjs tests/selection_stability_e2e.py
node scripts/e2e.mjs tests/repeated_word_e2e.py
npm run test:e2e
```

测试只使用隔离浏览器和本地服务。覆盖范围与完整结果见[验收记录](verification.md)。
