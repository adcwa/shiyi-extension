根因是 MutationObserver 将局部文字变动提交给 startScan，扫描入口每次先 clearAnnotations 再重新标记。标记数量始终正确，节点却不断被替换，造成正文闪烁。修复在清除前按当前原文、实际 Text 节点、词库 ID、片段范围、括号位置和释义检查现有结果；一致时直接保留节点，实际匹配变化时才更新。注入释义在源匹配中透明跳过，使单词边界和跨行内元素词组仍正确。

批次配置、映射与调色板专项（v0.5.0）

  • 每批块数默认为 16，可配置 1–64；字符与片段预算随块数扩展，默认 9600 字符／192 片段，整体上限 24000 字符／768 片段。
  • 真实加载生产扩展，分别观察到完整的 16、32、64 块请求。测试服务故意同时倒序返回块数组及片段数组；65 个段落的原 Text 节点、链接与强调文字全部按 ID 写回，代码保留；恢复时原 HTML 精确一致。
  • 故意遗漏第 10 块、重复第 20 块，只有这两块保留原文并失败；一次重试恰好只新增两个请求。
  • 浏览器实测调色板、原生取色器值、六位颜色值及预览同步；浅／深页面切换取对应颜色，悬浮与括号释义同步使用自选色。
  • 保存颜色不新增请求、不退出整页阅读，不改变块缓存身份。32 块请求在途时调整为 4 块并换色，已有任务完成且映射正确。
  • 选项刷新后保持，375、768、1024、1440px 设置页无横向溢出。
  • 过大响应与超时保留原文，提示减小每批块数；失败块可逐段重试。

默认 16 块的吞吐回归：120 个不同短段落共 9 次真实 HTTP 模型请求，重复运行新增 0 次；当前视口优先、独立配色与侧线检查通过。固定本地延迟测试不代表真实模型生成速度，记录见 verification/reader-throughput-0.5.0.json。

本机性能

固定本地文章 22425 字符、400 段，预置 10000 词条、800 处标记；检查页面长任务与鼠标悬浮到下一帧的响应时间（P95 目标不超过 150ms）。当前数值见 verification/extension-e2e.json 的 performance 字段。这组结果不包含真实模型网络耗时，也不代表所有网站和设备。

验证边界

  1. Chrome for Testing / Chromium 151 实测。本机未安装原生 Edge，Edge 使用同一 MV3 包，但原生安装仍需在目标设备确认。
  2. 按用户要求，生产清单使用 HTTP(S) 网站访问以实现默认开启。浏览器安装／升级确认及受管设备策略由用户和浏览器控制，不自动代点新增权限。
  3. 自动回归使用确定性本地 HTTP／SSE 服务。v0.9.1 额度诊断另有用户授权的 3 次真实拒绝响应，未取得成功翻译；该历史诊断不能作为总结真实厂家账户测试，也不能评价付费模型质量。
  4. 主文档可读文字为当前范围，PDF、OCR、iframe、Shadow DOM 和 Canvas 仍不支持。
  5. 本版本提供词库导出，暂不提供导入或云同步。
