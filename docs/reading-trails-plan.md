# 阅读轨迹与周期总结 · 需求和实施方案

2026-11-03 起草 · 2026-11-04 用户明确确认本轮完成全部功能 · v0.13.0 已实施

把访问过的网页，积累成可追溯、可持续提炼、可导出的个人知识库。

本文保留最初需求、实现思路和验收依据。用户于 2026-11-04 明确要求「这轮完成全部功能」，v0.13.0 已落地后台采集、持久轨迹、日周月年与专题回顾、定时补办和知识导出。当前行为以[阅读轨迹与回顾指南](knowledge-guide.md)和实际验收为准；下文最初建议中的可选导入、增量导出标记、单独阶段模型等不因此成为已交付承诺。

## 1. 用户需求

| 能力 | 要达到的行为 |
| --- | --- |
| 全网页后台总结 | 普通网页访问后自动排队总结，不以侧栏是否打开为条件；后台加载的已打开网页也可以处理 |
| 上下文 | 结合当前页正文、标题、栏目与必要的关联阅读上下文，避免只留下脱离语境的片段 |
| 本地保存 | 先把访问与可读取内容存下来，模型结果完成后持久保存到本地轨迹中 |
| 侧栏读取 | 打开侧栏直接读取当前页已有结果；正在生成则接续显示；没有结果则展示任务状态 |
| 黑名单 | 黑名单网站不采集、不发起新的总结；新增黑名单后停止该网站在途任务 |
| 每日总结 | 默认每天 18:00 再使用总结模型汇总；时间可以配置 |
| 周期积累 | 支持日、周、月、年的持续积累与总结，不停留在一次性网页摘要 |
| 查看与分析 | 查看自己的访问轨迹、各周期总结，并按主题、项目、来源等维度分析 |
| 知识导出 | 支持通用、可迁移的知识文件格式，保留来源、时间、引用与关联关系 |

核心闭环：访问网页 → 本地留存 → 后台总结 → 我的轨迹 → 周期回顾 → 知识提炼与导出。

**界面行为继续按标签页独立管理。** 后台自动总结全部符合条件的网页，不代表自动弹开全部网页的侧栏。侧栏仍专注总结和制品展示；翻译、词句库与设置保留原入口。

## 2. 访问采集与上下文

从功能实际上线后记录普通 HTTP(S) 网页的主文档导航、刷新及已加载正文。首次升级可检查当前已打开且可读取的标签页，先登记、再排队。不开侧栏、切到其他标签页，不应阻断已登记任务。

本轮“所有访问过”先按后续持续访问理解，不据此扫描或批量请求浏览器既有历史记录。浏览器内部页、商店页、内置 PDF、无可读取文字的页面及跨域框架沿用当前支持边界，记录明确状态，不伪造摘要。

| 上下文 | 保存与使用方式 |
| --- | --- |
| 网页基本信息 | 标题、站点、适合展示和导出的来源地址、访问时间、时区、语言 |
| 当前页内容 | 可读正文、章节标题、正文中的代码、表格和关键段落；保留截取状态 |
| 阅读来源链 | 本次访问由哪条已记录页面或阅读会话进入，保留关联记录 ID |
| 本地相关信息 | 与该页直接相关的已存词句、用户备注、少量相关页面摘要；附来源 ID |
| 来源与版本 | 正文内容指纹、采集时间、摘要版本、模型和提示词版本、上下文来源 ID |

不读取表单值、密码、编辑区草稿、隐藏内容、Cookie 或认证令牌；不为了补齐轨迹向历史 URL 携带登录凭据发起抓取。仅译文模式继续使用原始正文。页面内的指令是待分析资料，不能改变总结任务或扩大采集范围。

关联上下文应有边界：优先本次阅读链和直接相关的本地摘要，不把所有浏览历史拼进每次请求，也不把“打开过网页”写成“已读完、已掌握或已完成工作”。

## 3. 先保存，再总结

轨迹、页面内容和模型任务需要分开管理：

| 数据 | 作用 | 重复访问时 |
| --- | --- | --- |
| 访问记录 | 保存每次访问的时间、来源链和状态 | 增加一次访问事件，形成真实轨迹 |
| 正文快照 | 供后台任务在离开或关闭页面后使用 | 相同内容按指纹复用，不重复保存整份正文 |
| 页面摘要 | 保存一份内容版本的事实、要点和依据 | 正文和总结配置相同则复用已有摘要 |

采集到内容后，先在本地事务中写入访问、快照和待处理任务，再调用模型。标签关闭或浏览器后台服务重启后，已保存内容仍能继续处理。若页面在正文可读取前已关闭，只保存可取得的元信息和“内容未取得”状态，不生成猜测性总结。

正文没变化时，阅读会话或来源链变化只增加轨迹关联，避免每次访问因上下文细微变化重新总结整页。上下文变化可以进入后续日结和主题分析；确实需要重新判断语境时提供明确的重新总结操作。

页面摘要不再依赖最近 8 页的会话缓存。长期轨迹、摘要、引用与用户备注持续保存在本地，直到用户清理。卸载扩展、磁盘故障和浏览器存储异常仍需要依靠用户导出的文件恢复，不能把“本地保存”描述成永久备份。

## 4. 模型和后台任务

默认复用当前独立的总结模型及其默认、备用连接，不借用翻译模型或翻译 Key。页面、日结、周结、月结、年结均有各自场景提示词；首版不要求分别填写多套模型连接。若后续提供按阶段选模型，属于可选的业务设置。

后台采用持久化任务队列和有界并发。任务状态至少包含待采集、待总结、生成中、完成、部分完成、失败、因黑名单取消和已删除。服务重启要恢复任务状态，避免同一任务被多次同时领取。

- 相同内容、模型和提示词版本的页面任务去重；多个标签打开同一内容可共享结果。
- 同一周期和同一批输入只创建一次汇总任务，重复定时事件不产生重复请求。
- 总结已输出文字后保留部分结果，不因为网络抖动重新从头循环生成；备用连接继续遵守现有有限尝试规则。
- 失败、未配置模型或会话 Key 已失效时保留本地内容和任务状态，恢复连接后再续办，不丢轨迹。
- 展示实际请求次数，以及服务商明确返回的用量；没有返回的 Token 或费用标为未知，不伪造账单。

后台自动总结会扩大用量。页面已有结果应先复用，周期汇总优先读取已存摘要而非重复上传所有原文；资料过多时分批归纳，并保留分批范围和引用。具体并发、队列预算和大文档拆分值在实现时验证，不新增隐藏启动参数或默认关闭功能的临时开关。

## 5. 定时与每日总结

每日总结默认 18:00，可配置时间。保存时同时记录时区、任务覆盖区间和下一次计划时间。周、月、年任务等待其依赖的日结或月结完成后执行，不在同一时刻对同一批数据抢跑。

计划采用扩展的定时事件，并在后台服务启动时检查、修复定时登记。电脑休眠不会被闹钟唤醒，浏览器完全退出时也不能承诺准时生成；恢复运行后依据本地任务账本补办缺失周期，防止重复。不能只依赖后台的长时间计时器。[Chrome 定时事件说明](https://developer.chrome.com/docs/extensions/reference/api/alarms)、[后台定时教程](https://developer.chrome.com/docs/extensions/get-started/tutorial/service-worker-events)。

**18:00 不是自然日结束，统计口径需要明确。** 建议按自然日保存轨迹，18:00 生成“截至当前”的当日总结；18:00 后的记录仍属于当天，并在下一次计划更新时补齐相应日结版本。也可以选择“上次日结至本次日结”的阅读日口径，但必须让界面显示起止时间，不能默默把晚间访问归错日期。v0.13.0 采用自然日归档、计划时点阶段总结、晚到资料后续补齐版本。

每个周期任务记录输入快照、覆盖到的时间、尚未完成的页面数量和版本号。当天没有有效内容时直接显示空记录，不调用模型编造总结。截止时仍有页面任务未完成，则显示部分覆盖，后续合并补齐，不把未处理网页算作已总结。

## 6. 日、周、月、年的提炼关系

| 层级 | 主要输入 | 输出重点 |
| --- | --- | --- |
| 页面 | 原文快照及必要上下文 | 事实摘要、关键依据、概念、代码与来源 |
| 每日 | 当日有效页面摘要、访问链和用户备注 | 当天关注主题、关键收获、来源之间的联系与待核对问题 |
| 每周 | 当周日结及必要页面证据 | 持续关注的问题、主题变化、方案比较和未解决事项 |
| 每月 | 当月日结、可用的周结洞见及页面证据 | 主题脉络、重复出现的知识、阶段变化和重要来源 |
| 每年 | 当年月结及必要下层证据 | 长期关注方向、知识体系变化、主要结论及仍未解决的问题 |
| 专题 | 用户选择的时间、主题、项目或来源集合 | 跨周期关联、异同、证据冲突与知识卡片 |

不直接把每四份周报当成月报。周会跨月、月份天数不同；月结需要按当月的实际输入和来源集合去重。年结以自然年内的月结为主，也保留原始来源链。

上层模型不能只收到没有依据的浓缩文本。每条结论关联输入摘要 ID，重要判断带页面来源或对应摘录；事实、原文观点和模型推论分开。通过摘要向下展开，始终可以回到访问记录和原网页。后续资料更正或发现冲突时保留修订记录，不把旧结论静默改成新结论。

“不断提炼”通过新资料、周期调度和用户主动分析驱动，不意味着对没有新输入的内容无限循环调用模型。

## 7. 查看入口

在原管理界面增加两个正常业务入口：

- **我的轨迹**：按日期查看访问列表，支持标题、站点、主题、项目和处理状态筛选；查看页面摘要、上下文关系、原文依据及重复访问记录。可以编辑备注、归入项目、重新总结、删除或导出。
- **阅读回顾**：选择日、周、月、年和自定义范围，查看覆盖时间、输入数量、总结内容、引用、部分完成说明及历史版本；可按主题、项目或来源切换分析维度。

侧栏仍只服务当前页总结展示：先读取本地匹配结果，任务进行中则接收增量，尚未生成则显示排队或失败状态。打开侧栏不应另开一轮相同请求。设置、轨迹检索和周期调度配置留在管理界面，翻译入口保持现状。

## 8. 黑名单、删除与数据生命周期

黑名单检查覆盖采集、入队、开始请求、结果写入和周期输入选择。加入黑名单后停止相关在途任务，晚到结果也不得重新写入；移出黑名单恢复后续采集，不批量追溯抓取停用期间网页。

既有本地历史不因加入黑名单而自动删除，但默认不再进入新的模型汇总和知识导出。若既有日结或月结混入了现已停用的来源，需要标注依赖变化，后续从允许的下层证据重建；不能把这些旧汇总原样再次发送给模型，间接绕过黑名单。

删除某条轨迹或来源时，同步处理正文快照、摘要、引用和待执行任务，标记受影响的上层总结。旧任务不能把已删内容写回来。用户能清理原文快照、清理某站点记录、清理时间段或导出后清理；不能为节省空间静默丢弃已积累的知识。

长期数据建议独立保存在扩展自身的 IndexedDB，与词库和可淘汰的页面翻译缓存区分。容量检测和持久化保护需要纳入实现；IndexedDB 可在扩展后台使用，增长较大时评估持久化存储及扩展存储权限，不能按无限容量设计。[Chrome 扩展存储说明](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)。

## 9. 通用知识导出

首选同时照顾人工阅读与程序处理的格式：

| 格式 | 内容与用途 |
| --- | --- |
| Markdown + YAML 元信息 | 页面摘要、日周月年回顾、知识卡片；保留稳定 ID、标题、日期、标签、来源和相对链接 |
| JSON / JSONL | 保留结构化轨迹、摘要、版本、证据关系和元信息，供后续导入、检索或知识处理 |
| CSV | 导出访问时间线与统计索引，不把复杂知识关系压进一个无法恢复的表格 |
| 独立 HTML | 提供可阅读、可分享的回顾文档；使用本地样式，不附远程追踪 |
| ZIP 知识包 | 同时携带上述文件、说明、结构版本和校验信息，避免只有孤立摘要而丢失来源 |

建议的导出结构：

```text
dianyi-knowledge/
  README.md
  manifest.json
  visits.jsonl
  relations.jsonl
  pages/<stable-id>.md
  reviews/daily/<date>.md
  reviews/weekly/<period>.md
  reviews/monthly/<month>.md
  reviews/yearly/<year>.md
  topics/<stable-id>.md
  timeline.csv
```

元信息至少包含 `schemaVersion`、`id`、`kind`、时间与时区、统计区间、`sourceIds`、摘要版本、提示词版本和内容校验值。关系至少表达访问到页面、页面到摘要、摘要到周期结论的关联；导出的引用必须能定位到文件或来源。

不导出 API Key、认证令牌、会话 Cookie、认证缓存或含密钥的服务配置。默认知识导出包含已保存摘要、必要摘录和经过处理的来源地址；完整原文快照作为明确选择的导出范围。提供按日期、周期、主题和项目选择范围，以及增量导出标识。只承诺文件结构可解释，不提前宣称已验证所有第三方知识库的导入兼容性。文档使用 Markdown 和 HTML，不生成 Word。

## 10. 技术落点

以下保留设计落点；v0.13.0 已实现，对应模块与边界见[实现说明](architecture.md)：

| 位置 | 需要的变化 |
| --- | --- |
| 网页采集 | 在页面可读时采集原始正文和必要元信息，不依赖侧栏端口；支持导航和内容版本识别 |
| 独立知识数据层 | 新建访问、正文快照、摘要、关系、任务、用量记录等存储；本地事务写入和删除代次保护 |
| 总结执行器 | 将模型调用与页面实时存活解耦，接收已保存快照；维持流式输出、取消、备用和错误边界 |
| 侧栏控制器 | 保留按标签页独立打开，只订阅当前页匹配结果与任务状态，不充当自动总结的准入条件 |
| 周期调度 | 增加定时登记、任务依赖、时区、补办、输入版本和幂等检查 |
| 管理界面 | 增加我的轨迹、阅读回顾、时间与提示词配置、容量管理和导出入口 |
| 权限与说明 | 实现时加入所需定时权限，更新隐私说明和真实请求触发说明，不新增不必要的浏览器历史读取权限 |

当前相关基础包括 `summary-extract.js`、`summary-manager.js`、`summary-panel.js`、`summary-model.js`、`connections.js` 和现有管理界面。不能只移除可见性判断：目前执行器仍要在任务启动时读取活标签页，且结果只保存在会话中，直接去掉判断会丢失关闭页面后的内容，也不能形成可靠轨迹。

## 11. 交付顺序

1. **先保存完整轨迹**：持久化访问和正文快照，后台队列、黑名单、摘要复用、侧栏本地读取、轨迹查看，以及 Markdown / JSONL 导出。
2. **每日回顾**：可配置的 18:00 调度、时区、补办、覆盖区间、每日总结和查看；复用现有独立总结模型。
3. **周期提炼**：周、月、年、跨边界去重、版本与依赖更新，保证每条结论可以追溯。
4. **多维知识**：主题与项目视图、来源比较、知识卡片、跨周期分析和完整知识包导出。

这些是完整方向的分步实现，不把首版覆盖范围冒充全部交付。新增业务入口正常可用，不依靠额外启动参数开放。

## 12. 验收条件

- 不打开侧栏访问两个不同网页，均能生成本地轨迹与摘要；两页侧栏不会被自动弹开。
- 快速切页或关闭标签页后，已采集页面仍可总结；正文未取得时如实标记，不伪造结果。
- 反复访问同一内容保留访问次数，但不重复调用页面总结模型；正文实质变化形成新版本。
- 打开侧栏优先加载本地结果，进行中的任务继续显示，不额外创建重复任务。
- 黑名单、权限变化和删除能取消相关任务，晚到结果不会写回，其他站点任务不受影响。
- 到达配置时间生成对应日结；休眠、重启和重复定时事件不会漏掉已登记任务或重复结算同一输入。
- 18:00 后访问、跨日、跨周跨月、跨年和时区变化都有明确归属与覆盖范围。
- 上层总结只使用允许的有效来源，点击引用能回到具体轨迹；跨月周报不造成重复统计。
- 没有有效输入、部分失败、配置失效和空间不足时显示真实状态，不产生虚假的完整总结。
- 关闭并重启浏览器后仍能查轨迹与回顾；升级保留数据；导出文件能独立阅读和解析，引用完整且没有密钥。
